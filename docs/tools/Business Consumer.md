# B 端与 C 端产品

B 端（Business）服务组织，C 端（Consumer）服务个人。两者不只是"界面风格不同"，从需求来源到成功指标都不一样。

## 定义

`B` 端产品面向企业、商家、业务部门，使用者是岗位上的员工，付费方通常是组织；典型如 CRM、ERP、云服务控制台、内部中后台。

`C` 端产品面向个人消费者，解决生活场景里的具体需求；典型如外卖、音乐、短视频、社交。

`CRM`（Customer Relationship Management，客户关系管理）就是典型的 B 端系统：管理线索、客户、商机和跟进记录。

## 关键差异

| 维度 | B 端 | C 端 |
| --- | --- | --- |
| 用户 | 组织内的角色，按岗位划分 | 个人，边界模糊 |
| 决策链 | 长，采购、主管、IT 多方参与 | 短，用户自己决定 |
| 付费方 | 企业 | 用户本人或广告主 |
| 需求来源 | 业务流程与合规要求 | 用户痛点与情绪 |
| 设计重点 | 效率、密度、准确性 | 体验、留存、转化 |
| 成功指标 | 任务完成率、人效、错误率 | DAU、留存、转化率 |
| 迭代节奏 | 版本制，培训与迁移成本高 | 小步快跑，灰度实验 |

## 设计上的直接体现

- B 端页面信息密度高，表格、筛选、批量操作是主角，很少做花哨动效；
- C 端首屏就要抓住注意力，动效、引导、推荐位都是转化手段；
- B 端一次误操作可能造成业务损失，删除、批量操作要有二次确认和权限控制；
- C 端更在意"第一次使用的路径有多短"，注册、下单步骤越少越好。

## 常见误区

1. 把 C 端的视觉风格照搬到 B 端，结果是好看但操作效率低；
2. 把 B 端的复杂流程塞进 C 端，用户直接流失；
3. 只按"客户"需求做 B 端，忽略真正每天操作的"使用者"，导致上线后没人用；
4. 用 DAU 衡量 B 端产品——B 端更该看任务完成效率和错误率。

判断一个产品属于哪一端，最简单的办法是问：**谁付钱，谁每天在用，出错的代价是什么。**
